# Team rules: Brew & Build

- Write clean, production-style code and docs with meaningful names.
- Add comments only where the logic isn't obvious, written the way a human developer would. No "generated by" or tool attribution anywhere.
- Never run `git commit`, `git push`, `git merge`, or `git rebase`.
- NEVER submit or edit a hackathon entry (including `submit` and `posts`) without first showing exactly what will be submitted and getting an explicit "yes" from the user.
- Only edit files in the folders assigned to the current dev.
- Only Dev A edits package files, lockfiles, `.env`, and root configs.
- Repos are public: never commit secrets or API keys. Use environment variables.
